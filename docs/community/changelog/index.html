Changelog

All notable changes to this project will be documented in this file.

The format is based on Keep a Changelog, and this project adheres to Semantic Versioning.

[3.0.0] - 2026-10-16​

The 3.0 release, following 0.3.2. (Versions 1.0.0 to 2.1.0 of the package ID belong to an earlier, GPL-licensed line of the library and can't be reused.) It adds the guards people reach for first, a factory for custom exceptions, return values and Native AOT support, and from here on SGuard keeps a stable API under Semantic Versioning. Most code upgrades without changes; the upgrade guide covers the rest.

Breaking changes​

  • ThrowIf.* guards return the checked value instead of void: NullOrEmpty, GreaterThan, GreaterThanOrEqual, LessThan, LessThanOrEqual and Between. Calls compile unchanged, but this is a binary breaking change: an assembly compiled against 0.x that calls them must be recompiled. It is the only binary breaking change in 3.0 (30 methods, checked with ApiCompat).
  • GreaterThanException, GreaterThanOrEqualException, LessThanException, LessThanOrEqualException and BetweenException derive from ArgumentOutOfRangeException instead of directly from ArgumentException. catch (ArgumentException) still catches them, but catch (ArgumentOutOfRangeException) now does too, and a catch for one of them placed after catch (ArgumentOutOfRangeException) no longer compiles (CS0160). Their parameterless constructors have the default message of ArgumentOutOfRangeException.

Added​

  • ThrowIf.Null and Is.Null: only null fails, unlike NullOrEmpty. For a nullable value type, ThrowIf.Null returns the underlying value.
  • ThrowIf.NullOrWhiteSpace and Is.NullOrWhiteSpace.
  • ThrowIf.OutOfRange and Is.OutOfRange, which reject values outside an inclusive range: the opposite of Between, and the range check most code wants.
  • ThrowIf.Negative, NegativeOrZero and Zero, and their Is.* versions, for any number type (INumber<T>).
  • ThrowIf.Equal and NotEqual, and their Is.* versions, with StringComparison overloads for strings.
  • ThrowIf.NotDefined and Is.NotDefined for enum values that their type doesn't declare.
  • ThrowIf.LongerThan and ShorterThan, and their Is.* versions, for string lengths. Their messages never contain the string.
  • Is.Url (absolute http/https URLs only), Is.CreditCard (12 to 19 digits that pass the Luhn checksum) and Is.Match (a regular expression with a match timeout). They return false for null.
  • A Func<TException> factory overload on every ThrowIf.* guard. The factory runs only when the guard fails, so a passing guard creates no exception, and a lambda that doesn't capture variables allocates nothing.
  • New exceptions in SGuard.Exceptions: NullException (an ArgumentNullException), NullOrWhiteSpaceException, and OutOfRangeException, NegativeException, NegativeOrZeroException, ZeroException, EqualException, NotEqualException, NotDefinedException, LongerThanException and ShorterThanException (all ArgumentOutOfRangeExceptions). They name the argument expressions and leave values out unless SGuardOptions.IncludeValuesInExceptions is on, like the existing ones.
  • Nullable annotations: after ThrowIf.NullOrEmpty(x), x and the returned value are known not to be null; Is.Null, Is.NullOrWhiteSpace and the new validators are annotated with [NotNullWhen]; and a selector's parameter is no longer nullable when its root is.
  • Roslyn analyzers in the package: SGUARD101 (NullOrEmpty on a number or bool rejects 0 or false), SGUARD102 (an exception instance is created on every call; with a code fix that turns it into a factory), SGUARD103 (constant Between or OutOfRange bounds in the wrong order) and SGUARD104 (a selector that selects a whole object). See Analyzers.
  • Package validation against 0.3.2, so an accidental breaking change can't ship.
  • Trimming and Native AOT support. A CI job runs the trimming and AOT analyzers and publishes a test app with Native AOT that runs every guard.

Deprecated​

  • The ThrowIf.* overloads that take object[] constructorArgs (SGUARD001) and ExceptionActivator (SGUARD002). They create the exception with reflection, which the compiler can't check and which breaks under trimming and Native AOT. Pass a factory instead: () => new MyException(...). They will be removed in 4.0.

Changed​

  • The NullOrEmpty selector overloads are marked [RequiresUnreferencedCode] and [RequiresDynamicCode]: selectors don't work under Native AOT, so trimmed and AOT apps now get a warning where they call one. Nothing changes for other apps.
  • An empty Memory<T> or ReadOnlyMemory<T> is detected without compiling an expression, and the bounds check of Between no longer uses MakeGenericType. The bounds of a nullable struct that implements only IComparable<T> (not IComparable) are no longer checked against each other; every framework type implements both.

[0.3.2] - 2026-10-10​

A documentation release. The code is the same as 0.3.1.

Changed​

  • README, "Things that surprise people": the ThrowIf.LessThan plus ThrowIf.GreaterThan pair for rejecting values outside a range now has an example showing that the bounds themselves pass, and a new item notes that GreaterThan and LessThan are strict (>, <); use the OrEqual variants for >= / <=.

[0.3.1] - 2026-10-10​

A bug-fix release. It makes NullOrEmpty agree with its documented rules in more corners, fixes selectors that threw or enumerated a sequence twice, and keeps the performance of 0.3.0.

Highlights

  • NullOrEmpty no longer throws for default structs that are boxed, held by a nullable or behind an interface (ImmutableArray<T>, ArraySegment<T>, plain structs and tuples), and treats them as empty.
  • A selector reads a lazy sequence once (an IQueryable sends one query) and no longer keeps the first call's captured variables alive.
  • NaN upper bounds and NFloat.NaN fail comparison guards instead of throwing or passing.

Upgrading from 0.3.0

Some values that used to pass a NullOrEmpty guard now count as empty: a nullable enum or struct holding its default value (DayOfWeek? d = DayOfWeek.Sunday), a boxed default struct, enum or char, and through a selector a default char, nint or enum member. This matches the documented rule that default values are empty, and the result without a selector. An empty Memory<T> or ReadOnlyMemory<T> now counts as empty too, as an empty span already did.

Fixed​

  • A NullOrEmpty selector that selected a struct without an == operator (a plain struct, a tuple, KeyValuePair<,>, or a nullable of one) threw InvalidOperationException. It now counts as empty when it holds its default value, as it does without a selector.
  • A cached selector kept the first call's captured variables, and every object they reference, alive for the life of the process. The cache key no longer holds captured values.
  • A selector pointing at a framework class read all of its properties, so a relative Uri threw from Uri.AbsolutePath. Framework classes that are not collections (types in a System namespace, such as Uri or Version) are now only checked for null.
  • A default ImmutableArray<T> threw from a selector, and from Is.NullOrEmpty when boxed. It now counts as empty.
  • Is.Between and ThrowIf.Between with a NaN upper bound threw ArgumentException ("The minimum must be less than or equal to the maximum") instead of failing like any other NaN operand.
  • Is.Between with bounds of a type that implements neither IComparable<T> nor IComparable threw from the bounds check; such bounds are no longer checked against each other.
  • Nullable enums and structs holding their default value, and boxed default structs, enums and chars, didn't count as empty, and selectors on char, nint and enum members disagreed with the check without a selector.
  • With IncludeValuesInExceptions on, selector and span NullOrEmpty guards reported value=null in the message even when the value was an empty string or collection. These messages now leave the value out.
  • A boxed or nullable default ArraySegment<T> (or any struct sequence that throws from GetEnumerator when default) threw InvalidOperationException from NullOrEmpty. It now counts as empty.
  • A selector enumerated a lazy sequence twice (an IQueryable sent two queries). It is now enumerated once.
  • A selector threw when an IReadOnlyList<T>, IEnumerable<T> or object member held a default ImmutableArray<T>, which counts as empty without a selector. A selected value typed as object or an interface is now checked by the type of the value it holds.
  • An empty Memory<T> or ReadOnlyMemory<T> didn't count as empty, unlike its span.
  • With IncludeValuesInExceptions on, shortening a long value could cut an emoji or other surrogate pair in half.
  • NFloat.NaN passed comparison guards, unlike the NaN of double, float and Half.
  • SGuardCallbacks.OnSuccess and OnFailure accepted a null action, and the callback then failed silently. They now throw ArgumentNullException.
  • ExceptionActivator.Create let AmbiguousMatchException escape when the arguments fit more than one constructor (for example two nulls). It now throws InvalidOperationException, as for no matching constructor.

Documentation​

  • Corrected a span example that didn't compile on C# 12/13, a best practice that recommended Between where !Is.Between is meant, a stale note about the committed benchmarks, and the explanation of a callback example.

[0.3.0] - 2026-09-26​

A performance release. Guards run on every call of the code they protect, so this release removes their remaining costs.

Highlights

  • A passing guard no longer allocates and costs about as much as a hand-written if: about 1 ns instead of 5–13 ns and up to 160 bytes.
  • Selectors that capture local variables or use operators (+, ??, ?:, new) are cached like other selectors: about 0.5–1 µs per call instead of 50–85 µs and 9–10 KB.
  • Selectors whose path goes through an indexer, an array element or a method call (o => o.Items[0], o => o.Name.Trim()) work; they used to throw.
  • The benchmarks now run on .NET 8 and .NET 10 and report allocations.

Upgrading from 0.2.0

The public API is unchanged, so assemblies compiled against 0.2.0 work without being rebuilt. One behaviour change: Is.NullOrEmpty with a selector now applies the same rules as ThrowIf.NullOrEmpty, so a nullable value type holding its default value (int? x = 0) counts as empty.

Changed​

  • A passing ThrowIf.* guard no longer allocates. Guards used to pass a throwing lambda to an internal helper, which allocated a closure (and on .NET 8 a delegate) on every call, 32–120 bytes, even when nothing was thrown. A passing guard now costs about as much as a hand-written if (about 0.6 ns for an int comparison, down from 5–10 ns). Callbacks are invoked as before: Failure just before the guard throws, Success otherwise, with exceptions from the callback ignored.
  • Selectors that capture local variables (_ => captured.Name, o => o.Items[index]) are now cached like other selectors: the compiled delegate is shared and each call passes its own captured values. They used to be compiled on every call, about 85 µs and 10 KB each; a call now takes about 0.5 µs, most of it spent building the expression tree at the call site.
  • Selectors that use operators (+, ==, !, ...), ??, ?:, is, new or array creation are cached too; they were compiled on every call, about 50 µs and 9 KB each, and now take about 1 µs. Only selectors with a nested lambda, an invocation or a member or collection initializer are still compiled on every call.
  • Each value on a selector's path is read once. Paths were evaluated again for every null check, so a getter on the path ran once per level below it.
  • Is.NullOrEmpty with a selector now applies the same rules to the selected value as ThrowIf.NullOrEmpty. A nullable value type holding its default value (int? x = 0) now counts as empty for both, as it does without a selector.
  • Passing guards no longer box decimal operands on .NET 8. The argument null checks called ArgumentNullException.ThrowIfNull, which takes an object, and the NaN check matched type patterns on the operands; a passing ThrowIf.Between on decimal allocated 160 bytes.
  • NullOrEmpty checks a reference-typed value for collections before the value-type patterns and skips the default-value comparison, which is already covered by the null check: about 0.7 ns instead of 5–7 ns for a list or array.
  • Is.Any, Is.All, ThrowIf.Any and ThrowIf.All read arrays and List<T> as spans, so they no longer allocate an enumerator on .NET 8.
  • The ThrowIf.*<TException> overloads with a new() constraint create the exception with new TException() instead of reflection.

Fixed​

  • NullOrEmpty selectors whose path goes through an indexer, an array element or a method call (o => o.Items[0], o => o.Tags[0], o => o.Name.Trim()), or that combine members (o => o.First + o.Last), threw ArgumentException or InvalidOperationException while being compiled. They now work: a null on the path counts as empty, as with member paths, and other expressions are evaluated as written.
  • The XML documentation of Is.Between described the bounds as exclusive; both bounds are inclusive, as the code and the rest of the documentation state. The ThrowIf.Between<TException> string overload no longer calls the bounds an "allowed range".

Documentation​

  • Warnings that ThrowIf.Between throws when the value is inside the range, that NullOrEmpty enumerates lazy sequences (running IQueryable queries) and calls property getters when a selector points at a complex type, and that callbacks are not suitable for audit or security logging because their exceptions are swallowed.
  • The performance guide recommends Is.* over ThrowIf.* for input that is often invalid or can be sent invalid on purpose, since each rejected request pays for a throw (about 2 µs on .NET 10, 13 µs on .NET 8).
  • The benchmark results in SGuard.Benchmark/benchmarks/ are re-recorded on .NET 8 and .NET 10 with allocations, and the README summarises them. The benchmark project accepts BenchmarkDotNet's command-line options (--filter, --runtimes, --job).

[0.2.0] - 2026-09-26​

This release contains breaking changes; see Changed and Removed. Assemblies compiled against 0.1.2 must be rebuilt.

Added​

  • Is.Email validates email addresses with a built-in ASCII pattern (at most 254 characters, no trailing line break), or with a custom pattern that stops after Is.DefaultEmailRegexTimeout (1 second) or an explicit matchTimeout and then throws RegexMatchTimeoutException.
  • ReadOnlySpan<T> overloads for Is.NullOrEmpty, ThrowIf.NullOrEmpty, Is.All, Is.Any, ThrowIf.All and ThrowIf.Any.
  • SGuardOptions.IncludeValuesInExceptions to include checked values in built-in exception messages and Exception.Data. Values are written with ToString() and truncated to 64 characters.
  • The NuGet package now contains XML documentation (IntelliSense) and a symbol package (.snupkg) for Source Link.

Changed​

  • Built-in exceptions (NullOrEmptyException, BetweenException, GreaterThanException, GreaterThanOrEqualException, LessThanException, LessThanOrEqualException, AllException, AnyException) now derive from ArgumentException instead of Exception. ParamName holds the caller's argument expression (e.g. request.Age); the message is unchanged.
  • Built-in exceptions no longer include the checked values in Message or Exception.Data unless SGuardOptions.IncludeValuesInExceptions is enabled. When enabled, Exception.Data holds the formatted strings instead of the values.
  • ThrowIf.Between, GreaterThan, GreaterThanOrEqual, LessThan, LessThanOrEqual, NullOrEmpty and the matching Throw.*Exception helpers take optional [CallerArgumentExpression] parameters.
  • Comparison guards treat a floating-point NaN operand (double, float, Half) as failing: Is.* returns false and ThrowIf.* throws. NaN previously passed ThrowIf.GreaterThan/GreaterThanOrEqual and made Is.LessThan return true.
  • Is.Between and ThrowIf.Between throw ArgumentException when min is greater than max (for bounds of the same type, and for the string overloads). Reversed bounds previously matched nothing, so the guard never fired.
  • Is.All and ThrowIf.All on an empty ReadOnlySpan<T> (which arrays bind to on C# 14) now behave like the IEnumerable<T> overload and Enumerable.All: Is.All returns true and ThrowIf.All throws. Previously an empty array and an empty list gave opposite results.
  • The span overloads of Is.All, Is.Any, ThrowIf.All and ThrowIf.Any validate their arguments even when the span is empty.
  • Is.NullOrEmpty and ThrowIf.NullOrEmpty on a ReadOnlySpan<T> treat only an empty span as empty. A span whose elements were all null used to count as empty, while the same array or list did not.

Removed​

  • The net6.0 and net7.0 targets. The package targets net8.0, net9.0 and net10.0.

Fixed​

  • Selector-based NullOrEmpty guards cache compiled selectors by expression structure. The previous cache was keyed by expression instance and never hit, so every call recompiled the selector; calls are now roughly 40–50x faster with about 90% less allocation. Selectors that read captured variables are still compiled on every call.
  • Selector-based NullOrEmpty guards no longer overflow the stack on self-referencing or recursively generic types. A type already being inspected on the same path, or nested more than 8 complex types deep, is only checked for null. Indexed properties are skipped instead of throwing.
  • Selector-based NullOrEmpty checks on enumerable members dispose the enumerator they create.
  • ThrowIf.NullOrEmpty(value, selector) throws a new NullOrEmptyException on every failure, with a message naming the selector (e.g. Value 'o => o.Name' is null or empty.). It previously rethrew one shared instance, whose stack trace and data were overwritten by concurrent callers.
  • Built-in exception messages name the caller's argument expressions (e.g. left=request.Age). They previously always showed the guard's own parameter names (value=value).
  • ThrowIf.Any and ThrowIf.All invoke the callback once instead of twice.
  • ThrowIf.All and ThrowIf.Any no longer allocate their default exception when the guard passes.

[0.1.2] - 2025-10-14​

Added​

  • Added a "📊 Benchmarks" section to the main README.md, providing a direct link to the SGuard.Benchmark/benchmarks/ folder for easy developer access to performance results. (#28)
  • Ensured all benchmark results are discoverable and documented for each guard method (Is.* and ThrowIf.*), including All, Any, Between, GreaterThan, LessThan, and NullOrEmpty.
  • No breaking changes to the core library or APIs.
  • Improved developer experience and documentation clarity.

This update makes it much easier for contributors and users to find and review performance benchmarks for all guard methods.
